# SteppePlan — контекст для будущих сессий

> Этот файл фиксирует исходную идею, принятые решения и состояние работы.
> Читай его перед любой задачей в репозитории.

## Что это

**SteppePlan** — локально-автономное приложение для построения абстрактной концепции (логики) проектов и задач в виде графа: узлы — концепты, вопросы, решения, задачи, риски, знания; рёбра — смысловые связи между ними.

Главная особенность: приложение — не только холст для человека. Оно предоставляет **MCP-сервер**, через который ИИ-агенты (Claude, opencode, Cursor, локальные модели) читают и дополняют граф проекта, следуют заложенной логике и хранят знания прямо в приложении. Плюс встроенный чат с ИИ-провайдерами, который умеет менять граф инструментами (tool calling).

### Пользователь и сценарии

- У одного человека несколько проектов; в каждом — несколько концепций (графов).
- Человек набрасывает идею узлами и связями, как в Figma/Whimsical.
- ИИ-агент подключается по MCP: читает концепцию, предлагает/создаёт узлы и связи, отвечает на вопросы с опорой на граф.
- Встроенный ИИ-чат работает в контексте выбранной концепции и тоже может создавать/менять узлы.
- Данные лежат локально и работают без интернета. Облако, аккаунты и шаринг — опционально и позже.

### UX и визуальный язык

- Холст и панели в духе **Figma**: тёмная нейтральная тема, плавающие тулбары, панель слоёв/структуры, инспектор справа, мини-карта, точечная сетка.
- Простота и аккуратность в духе **Apple**: крупные скругления, спокойная типографика, минимум хрома, «дорогие» тени, понятные пустые состояния.
- Палитра Figma: синий `#0D99FF`, фиолетовый `#9747FF`, зелёный `#14AE5C`, красный `#F24822`, жёлтый `#FFCD29`; нейтральные серые. Поддерживается светлая тема.
- Интерфейс на русском. Тон текстов — короткий и человеческий, без канцелярита.

### Технические принципы

- **Local-first**: источник истины — файл на диске (`~/.steppeplan/workspace.json`, переопределяется `STEPPEPLAN_HOME`). Приложение работает без сети; внешние ИИ-провайдеры — опция.
- **Один общий слой данных**: локальный HTTP-сервер и MCP-сервер используют один store, поэтому правки агента сразу видны в UI (SSE).
- **MCP как первоклассный интерфейс**: инструменты для проектов, концепций, узлов и связей; ресурсы с графами. Агент должен уметь работать, не заходя в UI.
- **ИИ-провайдеры**: OpenAI-совместимые (OpenAI, DeepSeek, OpenRouter, Ollama) и Anthropic; ключи хранятся отдельно от рабочего пространства и не отдаются в UI. Есть офлайн демо-режим без ключа.
- **Стек приложения**: React + TypeScript + Vite, `@xyflow/react` для холста, Zustand, Node.js (нативный http) для локального API/SSE, официальный MCP SDK. Без облака и без аккаунтов.
- **Rust-путь**: в перспективе обернуть это в Tauri (Rust-бэкенд + webview) или перенести store/API на Rust. Приложение намеренно разделено на «webview» и «локальный демон», чтобы переезд был механическим.

## Где что лежит

- `AGENTS.md` — этот файл, продуктовый и технический контекст.
- Приложение живёт в корне репозитория (прототип повышен до рабочего приложения, отдельной папки `prototype/` больше нет).
  - `src/` — интерфейс: холст, панели, инспектор, ИИ-чат, настройки.
  - `server/` — локальный HTTP API, SSE, файловый store, прокси ИИ и tool-loop.
  - `mcp/server.mjs` — MCP-сервер (stdio) поверх того же store.
  - `desktop/` — Tauri-оболочка (Rust) и упаковка portable Linux-приложения.
  - `scripts/package-linux.mjs` — сборка релизного tar.gz, latest.json и SHA256SUMS.
  - `scripts/mcp-smoke.mjs`, `scripts/ai-smoke.mjs` — проверки MCP и tool-loop без внешних сервисов.
  - `docs/` — архитектура, MCP-контракт, роадмап и скриншоты.
- `README.md` — запуск, настройки, подключение провайдеров и агентов.

## Обязательный журнал через MCP

Это правило сильнее удобства: **все знания, указания пользователя, задачи, гипотезы и принятые решения каждой сессии фиксируются в SteppePlan через MCP**, а не только в чате, коде или коммитах.

- По умолчанию писать в проект **«SteppePlan»**, концепцию **«Разработка»** (создать, если её нет).
- Узлы: `decision` для решений, `task` для задач, `risk` для рисков, `source` для фактов и знаний. Связывать с существующим корневым узлом итерации, не дублировать.
- Теги: `task_001`, дата сессии, тип работы.
- Быстрый способ из репозитория: `npm run mcp:note -- --title "…" --summary "…" --type decision --tags task_001,решение --connect-title "…"`. Команда использует настоящий MCP-сервер и общий `~/.steppeplan`.
- Если MCP временно недоступен — записать в `docs/decisions.md`, а при восстановлении перенести в граф. Запись в файл не отменяет требование MCP.
- Никогда не записывать в граф API-ключи, токены, пароли и содержимое `secrets.json`.

## Соглашения

- Не ломать схему `workspace.json` без миграции: файл — пользовательские данные. При изменении схемы добавлять `schemaVersion` и миграцию.
- Идентификаторы узлов/рёбер/концепций глобально уникальны — MCP-инструменты адресуют их без пути.
- Все мутации проходят через `server/store.mjs` и увеличивают `revision`; UI синхронизируется по SSE.
- Секреты (API-ключи) — только в `secrets.json`, никогда не попадают в API-ответы и MCP.
- Сервер слушает `127.0.0.1`; это личный инструмент, без аутентификации в текущей версии.
- Новые визуальные элементы — в существующей палитре и с тех же радиусов/теней; не тащить UI-киты.
- Тексты интерфейса и README — на русском; код и имена — на английском.
- MCP-конфиг для OpenCode — только V2: серверы под `mcp.servers`, без поля `enabled`; конфиг перечитывается без перезапуска. Не возвращать V1-форму `mcp.<name>`.
- Перед изменениями в холсте помнить: `onSelectionChange` + управляемый `selected` у React Flow легко даёт цикл; выделение из store применяется точечно (sync/focus), а не эффектом на каждое изменение.
- Проверки перед сдачей: `npm run typecheck`, `npm run test:mcp`, `npm run test:ai`, `npm run build`.
- Linux-сборка: `npm run package:linux`; установщик — `desktop/packaging/install.sh`; обновления и откат — `docs/UPDATES.md`.
- Ключи провайдеров: писать в `secrets.json` **до** мутации workspace, чтобы `hasKey` в ответе/SSE был корректным; отвергать ключи с пробелами (частая ошибка — вставленная команда).
- Данные приложения (`~/.steppeplan`) и каталог установки (`~/.local/share/steppeplan`) разделены: обновление не должно касаться workspace.

## Состояние на текущий момент

- Приложение реализует: несколько проектов/концепций, граф узлов и связей, инспектор, поиск, авто-раскладку, локальное сохранение, live-синхронизацию, MCP-сервер, ИИ-чат с tool calling и демо-режим, настройки провайдеров, экспорт JSON.
- Проверено: MCP smoke-тест (инструменты + ресурсы), AI smoke-тест для OpenAI-совместимого и Anthropic tool-loop, ручные UI-сценарии (создание/связывание/удаление, drag, редактор, темы, live-правка агентом). Скриншоты — в `docs/screenshots/`.
- Связи на холсте — ортогональные (90°), авто-раскладка Dagre с увеличенными каналами; клавиатурный Delete, двойной клик и связи перетаскиванием проверены.
- Источник версии для UI и MCP — корневой `package.json`; desktop дополнительно передаёт `STEPPEPLAN_APP_VERSION`.
- Настройки вида: масштаб интерфейса 80–160%. В desktop используется нативный zoom webview (Tauri-команда `set_ui_zoom`, permission `allow-set-ui-zoom`, remote capability для 127.0.0.1), в браузере — CSS fallback; на 4K без сохранённого значения старт 120%. Textarea растут по контенту (`AutoTextarea`).
- Панели навигации и инспектора меняют ширину перетаскиванием разделителей (8px), значения сохраняются в localStorage; авто-раскладка использует измеренные размеры карточек, включая ресайзнутые.
- Адаптивные карточки: при заданной height текст перестаёт клампиться и занимает доступную высоту; теги показываются по ширине карточки (оценка ширины + «+N»), а не фиксированные 2.
- Таблицы: узлы `type=table` с `columns`/`rows`, рендер на карточке и редактор в инспекторе; MCP-инструмент `read_table` отдаёт Markdown/CSV/JSON. Старые поля project.schema/attributes в уже сохранённых JSON игнорируются.
- 0.1.4: две авто-раскладки — прежняя иерархия и компактная сетка; сохранённые размеры узлов, lane связей не сбрасываются. 0.1.2: ИИ-ассистент группирует **только новые узлы** рядом с якорем, не двигая пользовательскую карту; узлы ресайзятся за углы (`NodeResizer`, `width`/`height`); связи имеют увеличенную зону клика, ручное смещение lane (drag-хэндл + инспектор); авто-раскладка сохраняет lane.
- Linux-сборка 0.1.8: Tauri + встроенный Node, portable-архив с установщиком, ярлыком меню и MCP-wrapper. Обновление — манифест + sha256 + `steppeplan-update`. Релизный tar.gz хранится в `release/` и линкуется из README (GitHub отдаёт его как файл репозитория).
- Репозиторий подготовлен к публикации: README со скриншотами и быстрым стартом, MIT, `.gitignore`, версия 0.1.8. Исправлена рекурсия в `safeArrangeCreatedNodes` (ИИ-чат снова раскладывает новые узлы).
- Облако, совместный доступ, аккаунты, права и история версий — не реализованы (осознанно).
- Закрытые вопросы: Electron не используем, целимся в Tauri; хранение — файл, не IndexedDB, чтобы MCP и UI видели одни данные.
