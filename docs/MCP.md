# MCP-контракт

MCP-сервер (`mcp/server.mjs`) — это второй интерфейс к тому же графу, что и UI. Он работает по **stdio**, поэтому подходит для OpenCode, Claude Desktop, Cursor, Cline и любых клиентов, умеющих запускать локальный MCP-процесс.

Сервер не требует запущенного UI-сервера: он читает и пишет `$STEPPEPLAN_HOME/workspace.json` (по умолчанию `~/.steppeplan/workspace.json`). Если файла нет, при первом обращении создастся демо-пространство.

## Подключение

### opencode V2

Серверы в V2 лежат под `mcp.servers` (не под `mcp.<name>`):

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "steppeplan": {
        "type": "local",
        "command": [
          "node",
          "/абсолютный/путь/steppeplan/mcp/server.mjs"
        ]
      }
    }
  }
}
```

Проверка:

```bash
opencode mcp list
# ✓ steppeplan  connected
```

По умолчанию OpenCode включает Code Mode: инструменты доступны агенту как `tools.steppeplan.<tool>`. Конфиг перечитывается автоматически.

Если данные лежат не в `~/.steppeplan`, добавьте окружение:

```jsonc
"environment": { "STEPPEPLAN_HOME": "/path/to/space" }
```

### Claude Desktop

```json
{
  "mcpServers": {
    "steppeplan": {
      "command": "node",
      "args": ["/абсолютный/путь/steppeplan/mcp/server.mjs"]
    }
  }
}
```

После изменения конфигурации Claude Desktop нужно перезапустить.

Готовый JSON всегда можно скопировать из приложения: **Настройки → Данные и MCP**.

## Словарь графа

**Типы узлов**

| Значение | Смысл |
| --- | --- |
| `concept` | Идея, сущность, ветка смысла |
| `question` | Открытый вопрос, неопределённость |
| `decision` | Зафиксированный выбор и основание |
| `task` | Действие, двигающее проект |
| `risk` | Угроза, ограничение, цена |
| `source` | Факт, ссылка, исследование, знание |
| `note` | Свободная заметка |
| `table` | Таблица с колонками и строками |

**Типы связей** — направленные, `source --kind--> target`:

| Значение | Читается как |
| --- | --- |
| `supports` | источник поддерживает цель |
| `depends` | источник зависит от цели |
| `refines` | источник уточняет цель |
| `contradicts` | источник противоречит цели |
| `relates` | нейтральная связь |

**Статусы:** `open`, `active`, `done`, `parked`.

## Инструменты

### Чтение

| Инструмент | Аргументы | Возвращает |
| --- | --- | --- |
| `list_projects` | — | Ревизию, проекты, концепции, количество узлов/связей |
| `get_project` | `project_id`, `include_nodes?` | Проект и сводку концепций (опционально — компактные узлы) |
| `get_concept` | `concept_id` | Полный граф: узлы (включая таблицы) и все связи |
| `search_nodes` | `query`, `concept_id?`, `limit?` | Совпадения по title, summary, body и tags |

### Запись

| Инструмент | Аргументы | Поведение |
| --- | --- | --- |
| `create_project` | `name`, `description?`, `first_concept_name?`, `first_concept_description?` | Создаёт проект; опционально первую концепцию |
| `read_table` | `node_id`, `format?` | Читаемая таблица: markdown, csv или json |
| `create_concept` | `project_id`, `name`, `description?`, `color?` | Создаёт пустой граф |
| `add_node` | `concept_id`, `type`, `title`, `summary?`, `body?`, `tags?`, `status?`, `table?`, `connect_to_node_id?`, `relationship?`, `x?`, `y?`, `width?`, `height?` | Создаёт узел; для type=table принимает колонки/строки |
| `update_node` | `node_id`, любые поля узла + `table`/`x`/`y`/`width`/`height` | Частичное обновление, включая таблицу и размер карточки |
| `delete_node` | `node_id` | Удаляет узел и все его связи |
| `add_edge` | `source_node_id`, `target_node_id`, `kind`, `label?`, `concept_id?` | Создаёт связь; концепция выводится из source |
| `update_edge` | `edge_id`, `kind?`, `label?`, `lane?` | Меняет тип/подпись/смещение линии |
| `delete_edge` | `edge_id` | Удаляет связь |

Инструменты помечены аннотациями `readOnlyHint` / `destructiveHint`. Агент должен считать `delete_*` опасными и применять только по явной просьбе.

### Ресурсы

| URI | Содержимое |
| --- | --- |
| `steppeplan://workspace` | Все проекты и концепции с ID и количеством узлов |
| `steppeplan://concept/{conceptId}` | Полный граф концепции в JSON |

Список концепций-ресурсов динамический, с автодополнением ID.

## Таблицы

Узел типа `table` хранит данные в `table.columns` и `table.rows`. Он отображается на карточке и доступен агенту инструментом `read_table`:

```json
{
  "node_id": "nod_...",
  "format": "markdown"
}
```

Форматы: `markdown`, `csv`, `json`. Это удобный мост между визуальной таблицей и данными для модели/отчёта.

## Как агенту работать с графом

Рекомендуемый цикл:

1. `list_projects` → найти нужную концепцию.
2. `get_concept` → прочитать весь граф и модель данных проекта перед изменением.
3. При необходимости `search_nodes` (например, «не писал ли я уже про онбординг?»).
4. Зафиксировать результат: `add_node` с `connect_to_node_id` и осмысленным `relationship`; табличные данные — узлом type=table.
5. Для уточнений — `update_node`; для новых смысловых связей — `add_edge`.
6. Не дублировать существующие узлы; один узел — одна мысль.
7. Если данных не хватает — создать `question`, а не выдумывать ответ.
8. При нехватке данных — спросить или создать вопрос.
9. Не удалять и не переписывать чужое без явной просьбы.

Пример запроса агенту:

> Прочитай концепцию «Продукт» в SteppePlan, найди противоречия и слепые зоны. Зафиксируй выводы узлами: риск, решение или вопрос, свяжи их с существующими узлами. Не дублируй уже записанное.

## Синхронизация с интерфейсом

- MCP-процесс и UI-сервер — разные процессы, один файл.
- Сервер следит за файлом и отправляет SSE `change` с `source: "mcp"`; UI перечитывает workspace, показывает toast и фокусируется на первом новом узле активной концепции.
- Блокировка `.workspace.lock` сериализует read-modify-write, чтобы одновременные правки не терялись на уровне записи.
- Правки агента не требуют перезагрузки вкладки.

## Ограничения

- Один workspace на процесс; нет выбора пространства аргументом.
- Нет истории версий, отмены и diff-подтверждений.
- Нет вложений и внешних файлов — только текст, теги и ссылки внутри `body`.
- Нет авторизации: сервер доверяет локальному пользователю. Не публикуйте его.
- Контекст `get_concept` не пагинируется; для очень больших графов используйте `search_nodes`.
- `delete_node` удаляет связанные рёбра без корзины.

## Проверка

```bash
npm run test:mcp
```

Тест поднимает настоящий stdio-сервер на временном `STEPPEPLAN_HOME`, перечисляет инструменты, читает демо-граф, создаёт узел со связью, ищет его, читает ресурс и удаляет узел. Реальные данные не затрагиваются.

## Desktop-сборка

В Linux-приложении MCP-сервер лежит внутри установленного каталога. Установщик создаёт стабильную команду:

```bash
~/.local/bin/steppeplan-mcp
```

Она использует встроенный Node runtime и тот же `workspace.json`, поэтому агенту не нужен открытый интерфейс. Готовый конфиг всегда доступен в **Настройки → Данные и MCP**: в desktop-сборке команда указывает на встроенный Node и `app/mcp/server.mjs` установленного приложения.
